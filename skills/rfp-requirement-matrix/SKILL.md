# RFP requirement matrix and gap analysis

Finds every requirement in an RFP, including those hidden in running text, and checks each one against what the supplier can document. This is the backbone of the bid: every answer, risk and open question refers back to it.

Everything produced is an **AI draft**. Owners confirm.

## Communication

- Talk to the user in the language they write in. Keep requirement text in the language of the RFP.

## Before you start

1. **Documents.** You need the full RFP with all appendices that contain requirements. For the gap analysis you also need the supplier's capability source (product documentation, capability sheet, answer library). Ask for what is missing.
2. **Confidentiality.** For a real customer's RFP or internal material, confirm that this environment is approved or that names are anonymised before you continue.
3. **Large RFPs.** Work section by section and say which sections are done. Never claim the matrix is complete until every section is read.

## Step 1 – Requirement matrix

Find every requirement the supplier must meet or answer:
- requirements in tables with an ID,
- requirements in running text without an ID (use the section number as reference),
- formal requirements for the tender itself (language, deadline, signature, validity, page limits, reservations, answer format, conduct during the process),
- requests to "describe" something.

Rules:
- **Keep the buyer's IDs exactly as written** (for example Q-01, SEC-04). Without them the matrix cannot be traced back to the RFP.
- One requirement per row. Split a sentence with two separate obligations, but keep conditions that apply together in one row (for example "support in English and Norwegian, 24/7").
- Type: **shall** (mandatory: shall, must, will be rejected, qualification requirements), **should** (evaluated), **info** (request for information only).
- Category and suggested owner role: bid manager, sales manager, project manager, product owner, information security, commercial lead.
- Do not list background text, timeline dates or award criteria as requirements. List key dates separately.

## Step 2 – Gap analysis

For each requirement, using **only** the capability source:
- **Covered** – clearly met in full.
- **Partly** – met in part, only as a paid option, or a weaker version (lower service level, different time window).
- **Not covered** – clearly not possible.
- **Needs specialist** – the source says nothing that decides it (prices, signatures, contract acceptance, named persons, management commitments). Never guess.

Rules:
- Judge each requirement as a whole. With combined conditions, it is covered only if all are met at the same time.
- Compare numbers carefully: hours, percentages, time windows, retention periods. A stricter requirement than the capability is partly covered.
- If a requirement can be read in two ways, choose the stricter reading, say so, and add it as a clarification question.
- Reference the evidence (document and section or ID) and write one sentence on what is missing.

## Output

Deliver the matrix as a spreadsheet the team can sort and fill in, with these columns:

ID | RFP ref. | Requirement | Type | Category | Coverage | Evidence | Gap note | Owner | Status

- Status starts as **AI draft** for every row. Only a person sets Reviewed or Approved.
- Add a second sheet with key dates and a third with clarification questions to the buyer.
- In the reply, summarise: number of requirements and shall-requirements, how many are partly covered or need a specialist, and the 3–5 gaps that matter most for winning or for risk.
